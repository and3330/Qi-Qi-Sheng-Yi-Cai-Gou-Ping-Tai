# 七期生醫整合系統 說明書

最後更新：2026 年 11 月 17 日。這份說明書放在系統裡的 `/manual`，內部人員登入後可從管理後台或 ERP 的選單開啟。

## 一、系統總覽

整套系統有四個入口。商城、機構後台、管理後台共用同一組帳號；ERP 是獨立的一套，有自己的帳號。會員在商城下單並付款後，訂單每小時會自動進到 ERP 入帳，不需要人工轉單。

| 入口 | 網址路徑 | 使用者 | 主要用途 |
| --- | --- | --- | --- |
| 商城 | `/` | 醫院、診所藥局、消費者 | 瀏覽商品、下單、查訂單、知識專區、客服 |
| 機構後台 | `/portal` | 已審核綁定院所的醫院與診所會員 | 看全院所訂單、錢包、佣金、採購統計（只能查看） |
| 管理後台 | `/admin` | 系統管理員、營運、客服 | 商品與庫存、訂單出貨、會員與機構、內容、行銷、AI 助理、Bot 連線、AI 點數 |
| ERP | `/erp` | 有 ERP 帳號的內部人員 | 報價、銷貨、採購、庫存、會計、發票、人資薪資、專案、合約、資產、製造、品質、報表 |

管理後台負責「對外」的事（商品內容與庫存、訂單、會員、行銷）；ERP 負責「對內」的事（帳務、採購、人事、專案與公司營運）。

- **商城的商品庫存**在管理後台的「商品管理」調整，每次調整都有紀錄。
- **ERP 的庫存**是公司內部的料件與商品庫存，跟商城庫存分開計算。商城的每個商品在 ERP 會自動有一個同編號的品項（只記銷售、不扣 ERP 庫存）。想讓某個商品賣出時也扣 ERP 庫存、算銷貨成本，到 ERP「系統管理 → 外部串接 → 品項對應」把商品編號改對到有庫存的 ERP 品項。

## 二、帳號與角色

每個帳號有三個各自獨立的設定：會員身份決定看到的價格，後台角色決定能不能進管理後台，ERP 角色決定能不能進 ERP。

### 會員身份（決定價格）

| 身份 | 註冊方式 |
| --- | --- |
| A 醫院 | 專屬註冊連結 `/sign-up?type=hospital` |
| B 診所／藥局 | 專屬註冊連結 `/sign-up?type=clinic` |
| C 消費者 | 一般註冊頁 |

價格一律由系統依身份計算，會員無法自己更改身份，也只看得到自己那一級的價格。

**醫院、診所藥局身份要審核**：用專屬連結註冊後，帳號會先以一般會員（消費者價）建立，並標記「申請中」。系統管理員在「使用者管理」的「等級／院所」欄看到「申請：A 醫院」這類標記，按「核准」才會切換身份與價格，按「退回」則維持一般會員。

會員綁定院所是另一件事：綁定後要由管理員在「使用者管理」審核通過，才能看到全院所的訂單與使用機構共用錢包。

### 密碼

- **變更密碼**：會員在「會員中心 → 變更密碼」自己改，需要輸入目前的密碼。
- **忘記密碼**：登入頁按「忘記密碼？」輸入帳號，系統會把重設連結寄到該帳號設定的 Email。連結 30 分鐘內有效，只能用一次。
- 帳號沒有設定 Email 就收不到信，要請系統管理員在「使用者管理」重設。Email 可在註冊時或「會員中心 → 編輯個人資料」填寫。

### 後台角色（管理後台）

| 角色 | 可以做的事 |
| --- | --- |
| 系統管理員 | 全部功能，包含建立帳號、建立 Bot 金鑰、儲值 AI 點數、AI CMO |
| 營運 | 商品、訂單、內容、AI 助理、確認 Bot 送出的操作 |
| 客服 | 唯讀的後台資料與客服對話 |
| 一般會員 | 不能進管理後台 |

內部人員的帳號由系統管理員在「管理後台 → 使用者管理」建立，可指定角色與重設密碼。原密碼不會被讀取或顯示。

### ERP 帳號

ERP 有自己的登入頁（`/erp/`），帳號與商城分開。

- **第一次使用**：打開 `/erp/`，按「建立公司與管理員帳號」，填公司名稱、統編、管理員帳號密碼。這個入口只能用一次，建好就關閉。
- **新增其他人**：管理員在 ERP「系統管理 → 帳號管理」新增帳號並指定角色（老闆、管理員、主管、人資、財務、會計、業務、檢視者等），也可以自訂角色。
- **權限**：每個選單頁面能給哪些角色看，在 ERP「系統管理 → 選單顯示」與「角色管理」調整，前後端都會檢查。薪資、帳務等敏感頁面預設只有對應角色看得到。
- **忘記密碼**：ERP 登入頁有「忘記密碼」，會寄重設連結到帳號設定的復原信箱（要先設定寄信，見第八章）。

## 三、管理後台日常操作

### 訂單與出貨

訂單在「管理後台 → 訂單管理」處理，狀態只能依下表的順序往前推進。

| 目前狀態 | 可以改成 | 系統會自動做的事 |
| --- | --- | --- |
| 待付款 | 已付款、已取消 | 取消：退款、回補庫存、退回點數 |
| 已付款 | 已出貨、已取消 | 取消：退款、回補庫存、退回點數 |
| 已出貨 | 已完成、已退貨 | 完成：撥入分潤與會員點數 |
| 已完成 | 已退貨 | 退貨：退款、收回點數與佣金、回補庫存 |

- 出貨時可上傳出貨照片，會員在自己的訂單頁看得到。
- 可勾選多筆訂單批次改狀態；單筆有問題只會跳過該筆並說明原因。
- 只有已取消或已退貨的訂單可以刪除。
- 已付款的訂單每小時會自動進到 ERP 入帳（貨到付款的訂單在「已完成」後才進）；已經入帳的訂單之後取消或退貨，ERP 會自動記一筆退款。
- 付款方式有匯款、貨到付款、錢包扣款三種。
- 會員可以在自己的訂單頁取消「待付款」的訂單，效果與後台取消相同；已付款之後只能由後台處理。

### 匯款訂單

1. 系統管理員先在「訂單管理」右上方的「匯款帳號設定」填入銀行、分行、帳號、戶名，以及要給會員看的說明。
2. 會員選銀行匯款下單後，訂單頁會顯示匯款帳號與應匯金額。
3. 會員匯款後在訂單頁回報匯款帳號的後五碼，填錯可以重新回報。
4. 後台訂單列表的付款方式欄會出現「後五碼 12345」。對帳確認入帳後，把訂單改成「已付款」。

沒有設定匯款帳號時，會員的訂單頁只會顯示「匯款帳號請洽客服取得」。

### 商品庫存

商城的庫存在「管理後台 → 商品管理」調整：

1. 在商品列表的「庫存」欄按「調整」。有多種規格的商品，點進商品後在各規格那一列按「調整」。
2. 選「入庫（增加）」或「出庫（減少）」，填數量與原因（進貨入庫、盤點調整、報廢、退貨入庫、其他）。
3. 按「確認調整」。畫面會先顯示調整後的庫存，不能調成負數。

會員下單會自動扣庫存，取消或退貨會自動補回，這些不用手動調整。

### 分潤與點數

- **分潤規則**在「管理後台 → 利潤分享」維護：可依醫院、診所藥局、消費者或「全部」設定比例，每種身份同時只能有一條啟用中的規則。
- **入帳時機**：訂單改為「已完成」時，依訂單金額乘以比例入帳，每張訂單只入一次。
- **入帳對象**：下單人有已審核的綁定院所，就進該院所的機構共用錢包；沒有則進下單人的個人錢包。
- **報表**：管理後台可依機構、縣市、科室查看佣金；機構可在機構後台看到每一筆佣金明細。
- **會員點數**：訂單完成後每滿 NT$100 回饋 1 點，結帳時 1 點可折抵 NT$1。這與第七章的「AI 點數」是兩回事。

目前的分潤是單層回饋，沒有推薦人、上下線或多層分銷，也沒有錢包提領功能。

## 四、ERP 操作

ERP 是一套完整的企業管理系統，選單分成進銷存（報價、銷售、採購、庫存）、專案、合約、客服中心、資產、製造、品質、人事管理（組織員工、出勤打卡、請假、薪資）、財務會計（傳票、發票、收付款、請款、銀行對帳、報表）、系統管理。每一頁右上角的「？」有該頁的操作說明，左上角的搜尋（Ctrl+K）可以直接找單據與客戶。這一章只說明七期最常用的部分。

### 上線前設定

第一次登入後，儀表板最上面會列出「上線前設定」清單（假日、班制、職級、期初餘額等），照著逐項按「前往設定」完成即可。會計科目、預設倉庫在建立公司時已經自動建好。

### 專案

每一筆收入與支出都要歸到一個專案，報價單、銷貨單、採購單、請款單都要選專案才能存。商城訂單固定歸在「七期商城」專案；其他業務請先到「專案管理」建立專案。

### 商城訂單怎麼進 ERP

- 已付款的商城訂單每小時自動進來一次，變成一張銷貨單（編號開頭 `QIQI-SHOP-`），同時建立客戶、認列收入與銷項稅額。
- **會員等級會帶進 ERP**：客戶的「分類」會是「醫院會員」「診所藥局會員」或「一般消費者」，會員身份審核通過或變更後，下一次同步（每小時）就會更新，不用等他下單。
- 管理的地方在 ERP「系統管理 → 外部串接」：來源「七期商城」是系統自動建立的。按「立即同步」可以不等排程馬上抓；「收件匣」看得到每一筆的處理結果，失敗的會寫原因，修正後按「重試」。
- **商品自動對應**：商城的每個商品（依商品編號）在 ERP 會自動建立一個同編號的品項並對應好，新上架的商品下一次同步就會補上，所以 ERP 的銷售報表看得出每個商品各賣多少。自動建的品項只記收入、不扣 ERP 庫存；要扣 ERP 庫存並計算銷貨成本，在「品項對應」把商品編號改對到有庫存的 ERP 品項。沒有商品編號的明細才會記在「七期商城商品銷售」這個預設品項。
- 訂單款項會先記成「待撥款的應收」，實際入帳後在 ERP 做收款或對帳沖銷。

### 銷售流程

報價單 → 銷貨單 → 送貨單 → 銷售發票 → 收款。報價單可以直接轉成銷貨單；銷貨單確認後才會扣庫存、進入出貨流程。客戶可以設定信用額度，超過會提醒。

### 採購流程

請購／詢價 → 採購單 → 進貨單（收貨入庫、更新成本）→ 採購發票 → 付款。請款單走簽核流程，核准後才能付款。

### 會計

- **自動傳票**：發票、收付款、出貨、薪資等單據會自動產生傳票，不用手動切。這類傳票不能直接改，要從來源單據處理。
- **已入帳的單據要改或作廢**：會先送審，由財務或最高管理者核准後才生效，系統保留完整紀錄。
- **按月鎖帳**：鎖帳後該月份以前的帳不能再新增或修改。
- **報表**：損益表、資產負債表、現金流量表、試算表、日記帳、分類帳、應收應付帳齡、營業稅申報資料，都在「財務會計 → 報表」。
- **電子發票**：在「系統管理 → 串接金鑰」填入自己的綠界（ECPay）金鑰後，可以從 ERP 直接開立與作廢電子發票。

### 簽核與通知

請款、請假、採購等單據可以設定審批流程（選單的「審批流程」）。待簽核的項目會出現在右上角的通知與「我的頁面」。

### 手機使用與匯出

- ERP 可以加到手機主畫面當 App 使用；員工可以用手機打卡、請假、看薪資單。
- 每一頁右上角有「匯出」，可把目前的清單存成 Excel 或 CSV；單據可以列印或存成 PDF，版面在「列印模板」調整。

## 五、AI 助理

AI 助理在「管理後台 → AI 助理」，系統管理員與營運可以用。用打字問問題或交辦工作，它會直接查系統裡的資料回答。每送出一則訊息扣 1 點 AI 點數。

### 可以查的（8 項，直接回答）

| 類別 | 可以問什麼 |
| --- | --- |
| 訂單 | 訂單列表（可依狀態與天數篩選）、單筆訂單明細 |
| 庫存 | 低庫存清單 |
| 財務 | 銷售報表、財務摘要（營收、成本、毛利、佣金）、佣金報表 |
| 其他 | 待辦總覽（待審核、待付款、待出貨、草稿、低庫存）、知識庫查詢 |

### 可以做的（5 項專用操作＋後台通用操作，都要按確認才執行）

| 操作 | 說明 |
| --- | --- |
| 代會員下單 | 依會員身份計價，扣庫存 |
| 變更訂單狀態 | 付款、出貨、完成、取消 |
| 調整庫存 | 正數增加、負數減少 |
| 機構錢包儲值或調整 | 只有系統管理員可以執行 |
| 文章上下架 | 草稿、發佈、封存 |
| 後台通用操作 | 上面沒列到的後台功能都可以交辦：新增或修改商品與價格、審核會員身份、修改機構、設定分潤規則、新增或編輯文章公告、建立電子報、排程社群貼文等。AI 會先查清楚要填的欄位再提出 |

另外 AI 也可以查詢後台的任何資料（會員、機構、分潤規則、電子報、社群貼文、庫存異動等），不限於上面「可以查的」那幾項。

AI 不能做的事：設定密碼、建立或管理 Bot 金鑰、替自己按確認。

### 為什麼操作要按確認

會改動資料的操作，AI 只能「提出」，不能「執行」。流程是：

1. 你告訴 AI 要做什麼。
2. AI 複述操作內容（對象、品項、數量、金額），畫面出現「確認執行」按鈕。
3. 你核對無誤後按下按鈕，系統才執行。

在對話裡打「確認」「可以」不算數，一定要按按鈕。按鈕 10 分鐘內有效、只能用一次，系統執行的是當初存下的內容，不會被後續對話改掉。所有操作都有紀錄。

AI CMO、會員端客服、社群文案也是 AI 功能，但只提供分析或回覆，不會執行上表的操作，目前也不扣 AI 點數。

## 六、Bot 連線

外部 Bot（AI 代理）接上系統後，能用的功能與後台 AI 助理完全相同：查詢直接回答（8 項專用查詢，加上可以查後台任何資料的通用查詢），會改資料的操作（5 項專用操作，加上涵蓋後台全部功能的通用操作）都要有人在後台按確認。通用操作是用「按確認的那個人」的權限執行，所以營運去確認只有系統管理員能做的事會被拒絕；確認畫面會顯示 Bot 寫的白話說明與實際要執行的內容，請以實際內容為準。設定與確認都在「管理後台 → Bot 連線」。

商城和 ERP 各有一個連線入口：商城是 `/api/mcp`（金鑰在「Bot 連線」建立），ERP 是 `/erp-mcp`（金鑰設在部署環境的 Secrets，見第八章）。ERP 的入口可以查詢並操作 ERP 的所有模組；付款、發薪、作廢、刪除與系統設定仍然只能由人在 ERP 裡做。

要讓 AI 一次裝好兩個入口，把系統程式庫的 `docs/AI代理連線安裝說明.md` 裡「貼給 AI 的內容」整段複製、填上金鑰，貼給 AI 即可。

### 把 Bot 接上系統

1. 系統管理員進入「Bot 連線」，在「連線金鑰」按「新增金鑰」，取一個好認的名稱（例如「客服 Bot」）。
2. 畫面會顯示金鑰一次，立刻複製並妥善保存。關掉後無法再看，遺失只能刪除重建。
3. 複製頁面上方的連線網址（結尾是 `/api/mcp`）。
4. 在 Bot 的設定裡新增一個 MCP 連線：網址填上一步的連線網址，驗證方式選 Bearer，填入金鑰。

### 確認 Bot 送出的操作

1. Bot 要做會改動資料的事時，只會送出「待確認操作」，並回給使用者一個確認連結。
2. 系統管理員或營運點開連結、登入後台，在「Bot 連線」的「待確認操作」看到這筆，核對內容。
3. 按「確認執行」生效，或按「拒絕」取消。

- 待確認操作 60 分鐘內有效，每筆只能確認一次。
- 機構錢包儲值只有系統管理員能確認。
- Bot 沒有任何方法可以自己確認，也看不到別把金鑰送出的操作。
- 執行結果會留在「最近紀錄」，Bot 也可以查詢該筆操作的狀態回報給使用者。

### 金鑰管理

- 每把金鑰代表建立它的那位系統管理員，Bot 送出的操作都記在他名下。該帳號被停用或不再是管理員、營運時，金鑰自動失效。
- 可用開關暫時停用金鑰，或直接刪除；刪除後使用這把金鑰的 Bot 立刻無法連線。
- 建議每個 Bot 用一把自己的金鑰，出問題時可以單獨停用。
- 每個來源每分鐘最多 60 次請求。

Bot 每使用一次功能扣 1 點 AI 點數，查詢操作狀態不扣點。

## 七、AI 點數

AI 助理與 Bot 使用時會扣 AI 點數，點數用刷卡儲值。餘額、儲值與紀錄都在「管理後台 → AI 點數」。整個系統共用一個點數餘額。

### 扣點規則

| 使用方式 | 扣點 |
| --- | --- |
| 後台 AI 助理：每送出一則訊息 | 1 點 |
| Bot：每使用一次查詢或操作功能 | 1 點 |
| Bot：查詢某筆操作的狀態 | 不扣 |
| AI CMO、會員端客服、社群文案、每日自動報告 | 不扣 |

點數不足時，AI 助理與 Bot 會停止回應並提示儲值；儲值完成後立即恢復。商城、訂單、ERP 等其他功能不受影響。

### 刷卡儲值

1. 系統管理員進入「AI 點數」。
2. 在「刷卡儲值」選要買的點數，畫面會顯示應付金額。
3. 按「前往刷卡」，會跳到 Stripe 的付款頁輸入卡片資料。
4. 付款完成後自動回到「AI 點數」頁，點數立即入帳。

- 預設每包 100 點，US$10；實際價格以頁面顯示為準。
- 卡片資料由 Stripe 處理，系統不會儲存卡號。
- 只有系統管理員可以儲值；營運可以看餘額與紀錄。
- 若付款後沒有自動回到頁面，點數仍會在 Stripe 通知系統後入帳，重新整理頁面即可看到。同一筆付款不會重複入帳。
- 頁面若顯示「尚未開通刷卡儲值」，請聯絡系統服務商。

### 點數紀錄

頁面下方列出最近 100 筆異動：時間、說明（儲值、AI 助理對話、Bot 使用了哪個功能）、增減與餘額。後台沒有手動加點的功能，餘額只會因付款或服務商補點而增加。

## 八、系統設定（給管理者與服務商）

這一章的設定都在部署環境的 Secrets（環境變數），一般使用者不需要處理。金鑰類的值只能放在 Secrets，不要寫進程式或文件。

### 環境變數

| 名稱 | 必填 | 用途 |
| --- | --- | --- |
| `DATABASE_URL` | 是 | 資料庫連線 |
| `SESSION_SECRET` | 是 | 登入狀態加密 |
| `AI_INTEGRATIONS_OPENAI_BASE_URL`、`AI_INTEGRATIONS_OPENAI_API_KEY` | 是 | 原本的 AI 整合；圖片生成仍使用，必須保留 |
| `AI_PROVIDER_BASE_URL`、`AI_PROVIDER_API_KEY` | 選填 | 設定後，AI 助理、AI CMO、客服、社群文案的文字對答改走這個供應商；兩個都要填才生效 |
| `AI_MODEL_STRONG` | 選填 | 覆寫對答模型名稱 |
| `STRIPE_SECRET_KEY`、`STRIPE_WEBHOOK_SECRET` | 要開放儲值時必填 | 收款方的 Stripe 金鑰與付款通知簽章密鑰 |
| `AI_CREDIT_PACK_POINTS`、`AI_CREDIT_PACK_AMOUNT`、`AI_CREDIT_PACK_CURRENCY` | 選填 | 每包點數、價格（該幣別的最小單位）、幣別；預設 100、1000、usd |
| `AI_CREDITS_ENFORCED` | 選填 | 設為 `false` 可暫停扣點；預設會扣 |
| `RESEND_API_KEY`、`MAIL_FROM` | 要寄重設密碼信時必填 | 寄信服務的金鑰與寄件人地址（需為已驗證網域的地址）；電子報也用同一把金鑰 |
| `PUBLIC_BASE_URL` | 選填 | 系統對外網址；用於 Bot 的確認連結與付款後返回的頁面，未設定時取當下的網域 |
| `ALLOWED_ORIGINS` | 選填 | 另有其他網域要帶登入身分呼叫後端時填入，逗號分隔 |
| `ERP_AI_KEY_ADMIN` | 要讓 AI 代理操作 ERP 時必填 | ERP 連線入口（`/erp-mcp`）的全權金鑰，至少 24 個字元。另可設 `ERP_AI_KEY_SALES`（業務）、`ERP_AI_KEY_FINANCE`（財務）、`ERP_AI_KEY_READONLY`（唯讀），每一把都要不同 |
| `ERP_DB_SCHEMA` | 選填 | ERP 資料表所在的資料庫分區名稱，預設 `erp`，一般不用改 |

### 開通刷卡儲值

1. 在 Secrets 填入 `STRIPE_SECRET_KEY`。
2. 在 Stripe 後台新增一個付款通知（webhook），網址填 `系統網域/api/stripe/webhook`，事件選 `checkout.session.completed`。
3. 把 Stripe 產生的簽章密鑰填入 `STRIPE_WEBHOOK_SECRET`。
4. 重新部署後，到「AI 點數」頁確認儲值區塊已出現。

### 版本更新後第一次上線的檢查

- [ ] 啟動時系統會自動建立 Bot 金鑰表與 AI 點數表，確認啟動紀錄沒有錯誤。
- [ ] ERP 伺服器啟動時會自動建立、補齊 ERP 的資料表（放在獨立的 `erp` 分區，不會動到商城資料），確認 `/erp-api/healthz` 回應正常。
- [ ] 第一次啟用新版 ERP：打開 `/erp/` 建立公司與管理員帳號，再到「外部串接」確認「七期商城」來源已出現。
- [ ] AI 點數餘額一開始是 0，AI 助理會立即停用。先補點、儲值，或先設 `AI_CREDITS_ENFORCED=false`。
- [ ] 會計人員已知道：已入帳傳票不能再刪除，要改用作廢。
- [ ] 如有其他網域的網站會帶登入身分呼叫後端，已設定 `ALLOWED_ORIGINS`。
- [ ] 用一筆小額刷卡測試儲值，確認點數入帳。
- [ ] 建一把測試金鑰接上 Bot，試一次查詢與一次需要確認的操作。

### 服務商補點

後台沒有手動加點的入口。要贈點或補償時，由服務商在系統主機執行指令：

```bash
pnpm --filter @workspace/api-server exec tsx src/scripts/grant-ai-credits.ts 100 試用贈點
```

數字是要補的點數，後面是原因；這筆會出現在點數紀錄裡。

## 九、常見問題與目前的限制

### 常見問題

| 狀況 | 原因與處理 |
| --- | --- |
| AI 助理回「AI 點數不足」 | 餘額用完。請系統管理員到「AI 點數」儲值 |
| Bot 說連不上或回 401 | 金鑰輸入錯誤、已停用或已刪除，或建立金鑰的管理員帳號已停用。到「Bot 連線」檢查或重建金鑰 |
| Bot 說已送出，但資料沒變 | 操作還在等人確認。到「Bot 連線 → 待確認操作」按確認執行 |
| 待確認操作顯示「已逾時」 | 超過 60 分鐘沒確認。請 Bot 重新送出一次 |
| 找不到傳票的刪除按鈕 | 已入帳傳票改為「作廢」。只有草稿可以刪除，自動傳票要從來源單據處理 |
| 製令完工時說庫存不足 | 預設倉的原料不夠。先調撥或進貨到預設倉再完工 |
| 報價單不能轉訂單 | 檢查是否已接受、未過期、已綁定會員、商品上架且庫存足夠 |
| 會員用醫院連結註冊，卻看到一般價格 | 身份還沒審核。到「使用者管理」找到該會員，按「核准」 |
| 會員說沒收到重設密碼的信 | 帳號沒有設定 Email，或系統尚未設定寄信。由管理員在「使用者管理」重設密碼 |
| 會員找不到匯款帳號 | 尚未設定。到「訂單管理 → 匯款帳號設定」填寫 |
| 刷卡完成但點數沒增加 | 重新整理「AI 點數」頁。仍未入帳請聯絡服務商查付款通知設定 |
| 手機上看不到「匯出」 | 匯出按鈕只在較寬的畫面顯示，請用電腦或平板橫向操作 |

### 目前的限制

- **分潤**：只有單層回饋。沒有推薦人與多層分銷、不能依機構或商品設定不同比例、機構不能自行設定、錢包不能提領。
- **庫存**：商城庫存與 ERP 庫存分開計算；商城商品在 ERP 會自動有對應品項但不扣 ERP 庫存，要扣需在品項對應改對到有庫存的品項。
- **帳號**：ERP 帳號與商城帳號分開，沒有單一登入。
- **付款**：商城結帳尚未串接第三方金流與電子發票；Stripe 目前只用於 AI 點數儲值。
- **登入**：尚未串接 LINE 與 Google 快速登入；註冊時不會寄信驗證 Email。
- **通知信**：下單、出貨不會寄信通知會員；目前只有重設密碼會寄信。

每次改版的詳細內容記在系統程式庫的 `docs/系統更新日誌.md`。
